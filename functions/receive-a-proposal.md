# Receive a proposal

Read what somebody else's repository proved, and answer it.

## What it does

1. Measure it against the gate: agnostic, an improvement, verified.
2. Run the benches and the checks against it, as `prepare-the-door` does for a change of this
   repository's own.
3. Answer plainly, naming what was run. A verdict that names nothing is an impression with a
   format.
4. Teach where the proposal fell short of the shape rather than only rejecting it. Somebody did
   real work and sent it up.

## Where it is held

Only where proposals arrive, which is the blueprint. A copy holds this function and never has one
arrive, and that costs nothing: the function is the same everywhere and the traffic is not.

## Whether it has run

**The `verified:` line above answers that, and it is the only place that does.** The return flow
is the reason a blueprint exists, and a line claiming this function had run where it had not
would be the guess this system refuses.
