# CLAUDE.md

Entry point for Claude Code. The full specification is **`SYSTEM.md`**. Read it before doing anything substantive. This file carries only what must never be missed.

## Four hard rules

1. **Never work on `main`.** It is the template, not a workspace. If `git branch --show-current` says `main`, stop and say so. The guard hook enforces this mechanically. Template changes happen only through a pull request the Principal approves, and every one of them bumps the version of `SYSTEM.md` (SYSTEM.md §6, §8).
2. **Open every reply with the header** `[DD-MM-YYYY HH:MM TZ · <branch> · <agent-name>]`, built from the time and branch the anchor hook injects. Never build it from memory or estimation (SYSTEM.md §9).
3. **Push before the session ends.** All durable state lives in `memory/` on the agent branch. Work *on* that branch, and never accumulate memory on a chat's disposable one. Work that was not committed and pushed does not exist (SYSTEM.md §5, §6).
4. **Never install into a filesystem that will not survive the session.** The hook enforces this, and the attempt counts, not only the outcome. Unless the machine declares itself durable with `~/.chief-of-vibes-durable`, say the install cannot be made durable here. Put it in `memory/backlog.md` under **Principal**, and hand it to a local session. Never work around the block, and never commit a script that promises to install later (SYSTEM.md §4).

## Session start

- `memory/state.md` exists, so you are an agent. Read it, plus `memory/backlog.md` and any note in `memory/handoff/`, then apply SYSTEM.md §9. Check `knowledge/` on `main` before working out any procedure from scratch. A past agent may already have written it down, and rediscovering it costs a session for a conclusion already reached (SYSTEM.md §5). After a cleared window the anchor hook opens the session with that instruction itself, naming the notes. It is the machinery, not the Principal, so act on it and do not answer it as a question (SYSTEM.md §9).
- **What can this thing do?** `bash tools/skills.sh` prints every packaged capability, read from the skills themselves. Offer it when the Principal asks what is possible here.
- **Where is a rule?** `INDEX.md` maps every section, rule, skill and tool to where it lives. It is generated by `tools/index.sh`, so read it rather than searching, and regenerate it rather than editing it.
- No `memory/state.md`, so no agent starts and the system only listens. The anchor hook says which repository this is, by comparing `origin` against `.canon`. On the **canon**, offer to make their copy: the session creates the repository for them when it can, at step 0 of `.claude/skills/onboard/`, with *Use this template* as the fallback. The other offer is a template pull request, and no agent is created there. On the user's **own copy**, offer to create their agent through `.claude/skills/onboard/`, or a template pull request. When it is **undetermined**, say so and ask. Never guess. Greet briefly in the user's language, because they may not know what this is. Offer to continue an existing agent branch first when one exists. Act on evident intent without asking again.

Continuing an agent means checking out its branch with `git checkout <agent-branch>` and working there. The chat's own branch is scaffolding for template work only (SYSTEM.md §6).

If the anchor hook reported **template drift**, say so before substantive work and offer the sync: a pull request bringing the canon's template into this copy's `main`, then `tools/sync.sh` onto the agent branch. A rule that merged upstream is not in force here until that lands, and the hooks running in this session are the older ones (SYSTEM.md §6). If it reported the check unavailable, say that, rather than letting silence read as parity.

Reply in the language configured in `memory/state.md` under `language`. Never mirror the input language.
