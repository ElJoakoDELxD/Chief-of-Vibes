# Create the repository

Onboarding on the canon, or in a fresh clone of it, makes the user's own copy first. That is the
session's work rather than the user's, and it is real reach: a repository under their account,
created by a session.

## What is mechanical

Almost nothing, and saying so is the point. Where the session holds authenticated tooling it
creates the repository; where it does not, it says so plainly, names what it tried, and hands
over the *Use this template* button. The check is the account's own permissions, which the agent
did not grant itself.

## The rule that does the work

**Private by default.** The agent's memory will live there, and publishing it should be a
decision rather than an accident. Nothing enforces that but the procedure, so the procedure says
it in the step and this entry says it again where authority is read.

## Why it ends

The privilege covers one repository: the one being built. A founder that kept it would hold, on
every later session, the power to create repositories nobody asked for.
